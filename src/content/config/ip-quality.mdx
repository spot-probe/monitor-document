hub 能说出一台节点的 IP 在哪个城市、属于哪个 ASN、是不是 Tor 出口，以及几个公开风险库怎么看它。
这些信息**按节点授权**：没授权的节点，hub 既不查它，也不会把它的地址发给任何第三方。

## 两个来源，别混在一起

| | 本地 IP 库 | 在线风险库 |
|---|---|---|
| 谁提供 | 你自己下的库文件（MaxMind / DB-IP） | 第三方查询接口 |
| 查的时候出网吗 | **不出网**，本地读文件 | 把节点地址发出去问 |
| 给出什么 | 城市、国家、ASN、Tor 出口 | 风险标签（代理、机房、滥用记录…），**逐源并列** |
| 需要联网 | 只在**更新库文件**时 | 每次查询 |

本地库回答「这台机器在哪」，在线库回答「这个地址有没有被标记过」。两者互不替代。

## 本地 IP 库

**通用** → **IP 信息** → **IP 数据库（本地库）**，填三个地址（都可以留空）：

| 项 | 设置键 | 自动更新 |
|---|---|---|
| 城市库 | `geo_city_url` | 24 小时 |
| ASN 库 | `geo_asn_url` | 24 小时 |
| Tor 出口列表 | `geo_tor_url` | 1 小时 |

- 城市库与 ASN 库认 **MaxMind 的 mmdb**，也认 **DB-IP LITE** 的包
- 免费库的直链常常**带日期**，所以地址里可以用占位符按当次取库的日期展开：`{YYYY}`、`{YYYY-MM}`、
  `{YYYY-MM-DD}`。写死成某一个月的地址，下个月就 404，而症状是「IP 质量莫名变空」
- 免费的库几乎都发压缩包，hub 自己解开；落盘名**按内容判断**，不看你填的地址长什么样
- 库文件放在数据目录里，`--data-dir` 换到哪里它就跟到哪里
- **「够不够新」看文件自己的 mtime**：刚拉过就不会因为重启再拉一遍（127 MB 的库，重启一次重拉一次
  会把内存顶爆，然后是重启循环）
- 下载是**边收边写盘**、一次只下一份，所以内存占用与库的大小无关

填完点**保存 IP 数据库**，hub 立刻去取；之后按上表的周期自己更新。

## 在线风险库

同一个页签里配：一个 key 加一个开关。三个特点：

- **逐源并列，绝不合成**：几个来源各有各的判断，面板按来源分开列，不给一个笼统的「风险分」
- **有每日额度**：账本落在 `risk_day` 表里，只留最近 30 天
- **按节点授权**：见下

## 按节点授权：`--allow-ip-quality`

三件事都由这一个开关控制，**默认关**：

1. hub 要不要为这台节点**做本地查询**
2. hub 要不要把它的 IP **发给在线风险库**
3. 这台 agent 要不要**主动去探流媒体**（Netflix / ChatGPT / YouTube 等，见[流媒体解锁探测](/config/unlock)）

第 2 条是这个开关存在的主要理由：没有它，只要你在设置里填了 key，**每一台**节点的地址都会被发出去。
第 3 条同理——它让这台机器自己去访问那些站点，是一件应该由机器主人点头的事。

两道防线都挡：agent 侧不探（省掉出网），hub 侧也不收（老版本 agent 还在无条件探测，它报上来的结果
同样不落库）。没允许的节点在「节点实测」那一格显示**未允许检测**，与「还没测过」分开。

打开方式：纳管节点时勾**允许 IP 质量检测**，或重装时给 `--allow-ip-quality`。它写在服务的启动参数里，
**hub 读得到、改不了**——所以它只能由这台机器的主人决定。

<Note warn>
  这个参数是 **agent 1.1.10** 起才有的。老 agent 拿到它会以 `unknown argument` 退出，在
  `Restart=always` 下变成反复重启。**先升 agent，再勾这个框。**
</Note>

## 面板里在哪看

- **节点**页编辑某台机器：分别显示 **IP 质量**（城市 / ASN，以及来自本地清单的 Tor 出口）与
  **在线风险**（按来源列；开关关着时整块不出现）
- **总览** → **IP 质量**：把全队的结论摆成一张能横向比较的表，带国旗、坐标、时区，可以筛选
- 结论**失败一次不会抹掉上一轮**：每条结论各自带时间戳，面板会写出它有多旧

## 常见情况

**IP 质量一直是空的** → 先看这台节点有没有勾「允许 IP 质量检测」；勾了还空，看本地库是否下载成功
（设置页那个「已配置 / 未配置」与失败原因）。

**Tor 出口和在线风险里的 Tor 对不上** → 这是**两条路**：前者来自本地清单，后者来自在线库，
面板分开列，本来就可能不一致。

**换了个 IP 之后结论是旧的** → 结论绑在它被查的那个地址上，地址变了会自动判为过期。
