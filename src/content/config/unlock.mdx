agent 会定期主动访问几个流媒体站点，判断这台机器的出口能不能用它们：能解锁、只能看一部分、
还是根本不通。结果上报给 hub，在面板上以「节点实测」一列和一格一格的探测历史呈现。

## 探哪些、多久一次

| 服务 | 判据看什么 |
|---|---|
| Netflix | 两个自制剧页面，看是不是「这个区看不了」 |
| ChatGPT | 网页与 API 分别判，能分出「只通一边」 |
| YouTube | 页面标记；能分出「中国版」与「有广告」 |
| Amazon Prime Video | 一个页面 |
| Reddit | 结论就是状态码 |
| TikTok | 页面标记，能识别机器人拦截 |

**每 6 小时一轮**，并且按节点**错开相位**——全队不会在同一分钟一起去撞这些站点。探测"上一次是什么时候"
落在磁盘上（`StateDirectory`），所以**重启不会触发一轮新的**：装完之后立刻探一轮，之后按 6 小时走。

<Note warn>
  **这一项受按节点授权控制**：只有装了 `--allow-ip-quality` 的节点才会去探（默认关）。
原因是它会**主动访问这些站点**——出网行为该由这台机器的主人决定，而不是由接进来这件事默认决定。
没允许的节点在面板的「节点实测」那一格显示**未允许检测**。详见 [IP 质量与风险](/config/ip-quality#按节点授权--allow-ip-quality)。
</Note>

判据不是我们自己编的，照 [xykt 的 IPQuality](https://github.com/xykt/IPQuality)（`ip.sh`）里那套实际做法
移植，差异写在源码注释里。

## 结论怎么读

| 字样 | 含义 |
|---|---|
| 解锁 | 完全可用 |
| 解锁（机房） | 能用，但出口被识别成机房 IP |
| 仅自制 | Netflix：自制剧之外看不了 |
| 可用·无会员 | 能连，但受会员限制 |
| 仅网页可用 / 仅 App 可用 | ChatGPT：只通一边 |
| 中国区 | YouTube：走到了中国版 |
| 未解锁 | 明确不可用 |
| 没读明白 | 页面拿到了，但判据没命中——**不是「不可用」** |

「没读明白」要单独看：它多半是站点改了页面、或者连接被中途掐断。这两种情况的修法完全不同，所以
agent 提供了下面这条自检。

## 自检：`--probe-once`

```bash
sudo -u monitor-agent /opt/monitor/monitor-agent --probe-once
```

它跑一轮探测，把**每一份响应的事实**打到标准输出：URL、状态码、正文长度、以及几个标记各出现几次。
于是「读够了但标记是 0」（页面内容不同）与「只读到很少」（连接被提前关掉）一眼就能分开。

`--dump-body <目录>` 会把响应的正文也存下来，用于进一步对照。

## 面板里在哪看

- **节点**页的**节点实测**一列：每台机器当前各服务结论的摘要，只点名有问题的，正常的只计数
- 点开是**探测历史**点阵：一行一个服务，一格是一次探测（6 小时），横向铺开最近两周；
  点某一格能看那一次的具体结论。悬停会告诉你这一格测到了几次
- 历史在 hub 里留 **30 天**（`probe_history` 表），点阵只画最近两周是为了不把卡片撑高

## 与 IP 质量的关系

同一个授权旗子 `--allow-ip-quality` 管三件事：本地查这台机器的归属/ASN/Tor、把它的地址发给在线风险库、
以及**让它去探流媒体**。三件事都不做的时候，这台机器既不出网查、也不被查。

两边的数据各存各处、互不依赖：流媒体的结论在 `probe_history`（留 30 天），IP 质量的结论在节点的
质量列上（带它自己的时间戳）。
